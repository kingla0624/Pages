# 记账 App：新增账目与月度分析设计方案

建议保留现有 SwiftUI 架构和最低 iOS 17，用原生表单完成新增，用每日净支出柱图和分类支出构成回答分析问题。鲜明橙色承担品牌与主操作，Liquid Glass 主要出现在系统导航、工具栏和操作控件。金额、错误提示和图表使用稳定的内容背景。

本方案是设计交付，不包含 App 代码。目标是：用户能准确录入并知道账目是否已保存；能理解本月已同步的支出、退款和每天变化，并从同一数据口径进入明细。

**前提与版本边界。** 沿用已有账本、分类、货币及导航。本次没有提供项目源码，不能判断现有状态所有者、构建 SDK、后台接口或自定义导航覆盖情况。暂按一个账本一种币种、自然月统计、退款计入退款发生日期设计；实际实现须复用既有业务约定。多币种不能直接求和，没有明确汇率契约时按币种分开显示。

| 项目 | 本方案约定 |
|---|---|
| 最低部署版本 | 保持 iOS 17，不因设计参考升级最低版本 |
| 目标外观 | iOS 27 的原生系统外观；具体 OS build 与发布状态在实施时记录 |
| 构建 SDK | 当前未知；使用新 API 前检查实际 SDK，不安装或修改配置 |
| iOS 17–18 等低于 26 的系统 | 原生 Form、Sheet、导航、按钮与 Swift Charts；完整提供相同任务能力 |
| iOS 26 及以上 | 系统容器优先承接 Liquid Glass；必要的自定义控制才采用相关新 API |
| iOS 27 | 验证系统材质细化、Liquid Glass 外观设置以及宽窄窗口变化 |

Apple 说明，已采用 Liquid Glass 的 App 在 27 系列系统上会获得材质细化，并响应新的外观设置。首次采用仍需检查 SDK、系统组件和现有外观覆盖；不能仅凭“SwiftUI 项目”判断已完成适配。[WWDC26：Platforms State of the Union](https://developer.apple.com/videos/play/wwdc2026/102/)、[Adopting Liquid Glass](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass)

**新增账目：一张可滚动的任务 Sheet。** 从现有账目页工具栏的“新增账目”按钮进入。新增是动作，无需增加一个执行新增的 Tab。Sheet 内保留独立 NavigationStack，顶部标题“新增账目”，左侧“取消”，右侧“保存”。起始使用大高度，让金额、分类及键盘有空间；宽窗口由系统决定合适呈现宽度，内容不无限拉长。

表单按照“金额 → 分类 → 日期 → 备注”的顺序组织。金额是一组，分类和日期为一组，备注为一组。分类数量多时，在同一 Sheet 的导航栈内进入单选列表，显示当前选择，返回保留所有输入；不用再堆叠第二张选择 Sheet。

| 字段 | 用户看到的内容与规则 | 错误与输入边界 |
|---|---|---|
| 金额 | 持久标签、账本币种和较醒目的金额；必填，默认空白。默认支出，可在金额组中切换“支出／退款”，输入绝对金额 | 类型选择只是金额符号的输入辅助，仍然只有四个持久字段；提交时支出为正、退款为负。若原 App 已有类型入口，直接复用。拒绝零和超出既有业务范围的金额，允许的精度随币种与既有接口；不默默截断小数 |
| 分类 | 必选；显示选择后的名称。没有可靠默认时显示“选择分类”，不随机预选 | 分类被删除或服务端判定不可用时，保留其余字段并要求重新选择；没有可用分类数据时说明原因并提供重新加载 |
| 日期 | 系统 DatePicker，默认账本语境中的今天，只选择记账日期 | 日期范围沿用业务规则，不能凭设计擅自支持未来记账。显示、提交与统计使用相同日历和时区语义 |
| 备注 | 明示“选填”，允许多行；键盘焦点与滚动保持自然 | 保留中文组合输入、换行、粘贴和长文本。长度限制取自真实接口；超限就地说明，不截掉内容 |

金额内部采用 Decimal 或货币最小单位整数，输入过程中保留原始文本，避免每个按键都重排格式。小数键盘不提供可靠的负号入口，所以通过“支出／退款”控制符号；负号粘贴应被识别并与类型一致，不产生双重取负。解析尊重地区的小数和分组符号；显示金额必须有币种语境，错误靠近字段，例如“请输入大于 0 的金额”。初次进入可聚焦金额，但要验证大字号与键盘下分类、取消和保存仍可达。

**保存与离开是一套明确的状态契约。** 草稿只在当前会话内存中保留；这不等于已记账，也不承诺退出 App 或进程被终止后恢复。保存成功必须由服务端确认，网络断开时不能显示“已保存”或“稍后自动同步”。

| 状态／事件 | 界面与行为 |
|---|---|
| 空表单、没有修改 | 可直接取消或下拉关闭，不弹丢弃确认 |
| 已输入但未提交 | 正常编辑。保存前完成本地校验；可提交条件不满足时提供可读的原因，不仅留下灰色按钮 |
| 取消已修改内容 | 弹出“放弃这笔未保存的账目？”；选择“继续编辑”或“放弃账目”。未保存时禁止直接下拉关闭，保留可发现的“取消”路径；分类子页的返回只退出选择页 |
| 保存中 | 保存按钮显示不确定进度和“正在保存…”；防止连点及键盘重复提交。提交的是冻结的字段快照，等待期间不允许改动该快照。保留可达的离开入口 |
| 已知尚未发送／确定失败 | 就地显示“尚未保存，请联网后重试”或可行动的具体原因，恢复编辑，保留金额、分类、日期、备注。允许取消并按未保存规则退出 |
| 服务端字段拒绝 | 展示对应字段问题，保留其余输入；用户修正后提交。登录失效若需要重新认证，沿用现有流程并尽可能保持当前会话草稿，不虚构新的恢复能力 |
| 超时、连接中断，服务端结果未知 | 显示“暂时无法确认是否已保存”，先查保存结果。不能把超时直接当成未保存并自动再创建；也不能无限转圈 |
| 等待中选择离开 | 提示请求可能已经送达，离开不会撤回服务端保存。停止客户端等待不代表取消记账；保留本次请求身份用于后续确认，若现有系统做不到，明确只能返回账目页检查。不要宣称草稿或请求在 App 重启后一定可恢复 |
| 服务端确认成功 | 合并服务端返回的唯一账目，关闭 Sheet，回到发起位置，以可读反馈显示“账目已保存”。刷新受影响列表／分析，按记录身份去重；触觉仅作可选补充 |

防重复必须覆盖“请求已被服务端接受、响应丢失”的情况。建议沿用或增加服务端支持的幂等请求身份与结果查询：同一次提交和重试使用同一身份，确认失败后修改内容才创建新的提交身份。这是需要核实的接口契约，不能只靠禁用按钮实现。如果接口没有幂等或可核实结果的能力，结果未知时不提供可能重复创建的一键重试，应引导检查账目；“可安全重试且不重复记账”要等这项接口条件满足后验收。

保存与分析刷新也是两件事：记账成功而分析刷新失败时，显示“账目已保存，分析尚未更新”，不要重新创建账目。分析原有数据保持可读并带更新时间。

**月度分析：从总额到每日，再到分类。** 放回现有分析目的地；月份是当前分析的条件，使用月份选择控件及明确的上／下月按钮。页面为纵向滚动内容：月份与数据状态 → 总额摘要 → 每日净支出 → 分类支出构成 → 全部明细入口。无需把每一项都做成相同大小的玻璃卡片。

顶部先显示“已同步净支出”，主金额下方并列“支出”和“退款”。同步未完成时显示“部分数据”，并写明未同步日期、今天统计截止时刻和最近成功更新时间；这些状态不能只藏在帮助气泡中。数据完整的历史月份才可使用完整月份总额文案。当前月份不与完整上月直接生成“下降了多少”结论，本期暂不增加环比。

统计口径如下，视为本方案的产品数据约定：

| 概念 | 定义 |
|---|---|
| 原始流水 a | 支出 a > 0，退款 a < 0；不取绝对值后求净额 |
| 支出 E | 当前范围、币种、有效记录中所有正值之和 |
| 退款 R | 所有负值绝对值之和，单独用正金额配“退款”标签展示 |
| 净支出 N | 带符号求和，即 E − R；可以为负，负值表示本范围退款超过支出 |
| 每日 | 以账本 Calendar、TimeZone 的日边界分桶，使用半开区间 [当日开始, 次日开始)，不是固定 86400 秒。退款按流水记账日进入当日，不擅自回写原消费日 |
| 本月 | 自然月边界；当月仅统计到当前截止时刻。未来日期不标成未同步，也不补为真实零 |
| 分类 | 每笔流水归入一个稳定分类身份；无分类记录纳入明确的“未分类”，不静默丢掉。删除／改名后的展示遵循现有记录归属规则 |
| 完整性 | 每日除了数值还需要完整／部分／未同步状态及适当的截止时刻；仅凭“没有记录”不能区分真实零与未同步 |

如果接口没有每日完整性信息，必须把可判断的范围标为“完整性未知”，不能自行把无记录日染成零。当前净额不一定是最终净额的下限，后续支出和退款都可能改变它。

**每天变化使用以零为基线的净支出柱图。** 横轴是真实日期，纵轴为同一币种金额；正值向上、负值向下，零线清晰。日累计流水适合柱图，默认不加平滑折线，避免让缺失日期看起来连续。为本月 28–31 天保留概览，减少轴标签密度而不是删日期。单月初版不同时增加横向滚动，先降低图表点选与页面竖滑竞争的复杂度。

| 日期情况 | 图上表达 | 选择后的文字 |
|---|---|---|
| 完整且有记录 | 实心柱，保留正负方向 | 完整日期、净支出、支出、退款、笔数，以及“查看当日明细” |
| 完整且没有记录 | 零线上的零值标记，不造出有高度的柱 | “当日无账目，净支出 ¥0.00” |
| 有支出与退款但净额为零 | 零值标记；信息中保留真实流水数量 | “净支出 ¥0.00”，同时展示支出、退款及明细，不能写“没有消费” |
| 未同步 | 该日期位置留空，配下方状态带／文字标记；不输入数值 0 | “该日尚未同步，金额未知”，提供同步入口，不吸附到邻近有值日期 |
| 今天部分记录 | 当前已知净额仍按比例绘制，附“截至 HH:mm · 部分”标签和可区分的描边／标记 | 同时读出截止时间、部分状态和数值；不能只改变透明度 |

选择落在日桶内，而非无条件寻找最近有值点。选中信息固定放在图下方，避免大字、边缘日期和手指遮挡；选择后保留到用户选择另一日、清除或切换月份。刷新时按日期身份保留选择并更新数值与完整性；切换月份清除旧选择。使用清楚的“查看当日明细”按钮进入过滤列表，返回时保留月份、选中日期和滚动位置。

Swift Charts 的 `chartXSelection(value:)` 从 iOS 17 起提供值绑定，业务层仍需把原始日期匹配到具体日桶。这里采用系统选择能力并验证实际点选／拖动行为，不预先铺一个抢占整张页面的自定义拖拽层。[WWDC23：Explore pie charts and interactivity in Swift Charts](https://developer.apple.com/videos/play/wwdc2023/10037/)

**分类构成使用横向支出条形图与精确列表。** 标题明确为“已同步支出构成（不含退款）”。每类柱长编码 E_c，零基线统一，按支出金额降序，同值使用稳定次序；类别标签、金额和百分比直接可读。分母是所有类别正向支出之和 E，百分比为 E_c / E。图下每类同时显示“支出、退款、净额”，所以退款不会从分析中消失。点击该类进入同月同类别的全部流水，保留退款；若用户从“支出”明细入口进入，则明确带上正向流水过滤。

这样既回答“支出由哪些类别组成”，也能看到退款对每一类的影响。不能把有符号净额直接塞进饼图或用绝对值让占比凑满 100%。净额为负的类别仍显示在分类列表中；只发生退款、没有正向支出的类别也必须可找到。当 E = 0 时不计算占比，显示“本期暂无支出”，仍列退款和净额。类别较多时概览可只显示前几类，但“其他”必须等于剩余正向支出之和，并有展开全部分类的入口；退款和未分类记录不能被这个汇总隐藏。

例如，某类支出 ¥100、退款 ¥150，其净额是 −¥50；构成使用 ¥100 占全部正向支出的比例，列表清楚显示退款 ¥150 和净额 −¥50。这是两个不同问题的明确表达，不把负净额解释成负面积。

**明细必须是可发现的等价阅读入口。** 每日图下提供“按日查看”，分类区提供“全部分类”，页面提供“本月全部账目”。列表显示完整日期／分类、金额符号与“支出／退款”文字、备注，以及当前范围的数据状态。用户无需精准拖动图表就能选日期、查零值或未同步日、进入记录详情。每日、分类与总览使用相同的筛选快照与口径；刷新不能让旧月份结果覆盖新月份。

**橙色与玻璃的具体分工。** 新增入口和保存的优先级使用品牌橙；金额重点、正向数据和少量内容强调延续品牌。退款使用独立且稳定的样式与文字标签，方向和正负号仍是信息主体。分类横条可统一使用橙色深浅之外的同一稳定橙色，由位置和标签区分类别，避免强行制造过多系列色。错误使用系统语义样式和说明，不与品牌橙混成一个含义。

导航栏、工具栏、Sheet 按系统默认表达材质，不再外包一层自定义玻璃。表单分组、文字、总额和绘图区使用语义背景；这个任务没有富媒体背景，自定义浮动控制如确有必要从 regular 开始，clear 没有实际收益。Apple 将 Liquid Glass 用于浮于内容上的导航与控制层，并将 clear 限定在视觉丰富背景上的适当控制；本方案据此让账目内容保持清晰。[HIG：Materials](https://developer.apple.com/design/human-interface-guidelines/materials)

正文用系统语义字号，金额可使用相应的大字号与等宽数字；人民币只是示例，最终按账本币种与 locale 格式化。大字号时金额和单位可重排，分类标签增高，图表摘要与图例改为纵向，不统一缩小文字。窄窗口单列，宽窗口可把每日与分类区并排，但总额与完整性说明仍先读到；以实际可用宽度决定布局，不按设备名写死。橙色资产需准备浅深色和高对比变体，具体色值与对比结果留待实际渲染验证。

**关键 SwiftUI 映射。** 这些是实现方向，不代表已在当前项目编译。

| 设计部分 | 最小原生映射 | 实施边界 |
|---|---|---|
| 新增任务与分类选择 | `Button`、`.sheet(item:)`、`NavigationStack`、`Form`／`Section`、`NavigationLink` | 使用现有呈现宿主与草稿状态所有者；选项页返回保留草稿 |
| 保存、取消、保护输入 | `.toolbar`、`ToolbarItem` 的确认／取消语义、`ProgressView`、`.confirmationDialog`、`.interactiveDismissDisabled`、环境 `dismiss` | `onDismiss` 不是保存成功；禁用交互关闭不自动生成丢弃确认。异步提交与错误状态需要真实状态管理 |
| 四个字段 | `TextField`、`Picker`、`DatePicker`、`TextEditor`、`FocusState`、`.scrollDismissesKeyboard` | 键盘类型不等于金额校验；持久标签、中文输入、地区解析与服务端约束另处理 |
| 分析布局与精确值 | `ScrollView` 加 stack／`ViewThatFits`；明细使用 `List`／`Section`、`LabeledContent` | 不在 List 外叠同向 ScrollView；大字时保留全部关键值及入口 |
| 每日图 | `Chart`、`BarMark`、零线 `RuleMark`、必要零值 `PointMark`、`chartXSelection(value:)` | `Charts` 模块；正负域包含零；缺失桶不生成伪零 mark。Chart／基础 marks 的 iOS 16 基线低于本项目最低版本，选择使用 iOS 17 能力 |
| 分类图 | 横向 `BarMark`，类别稳定身份、统一零基线与精确数值行 | 汇总和百分比分母由数据层决定，不交给 mark 自动推断；避免重复类别 mark 意外堆叠 |
| 局部刷新与空／失败 | `.refreshable`、`ContentUnavailableView`、就地状态与重试 `Button` | 空数据、未同步、加载失败分别处理；已有内容刷新时不整屏清空 |
| 玻璃 | 优先系统导航和工具栏；自定义时才用 `glassEffect(_:in:)` | 已核实 iOS 26 起。运行分支使用 availability；旧 SDK 仍需能够识别新符号，`if #available` 不能代替构建 SDK 支持 |
| 无障碍与偏好 | 默认控件语义；必要的 `.accessibilityLabel`／value、图表描述；`accessibilityReduceMotion`、`accessibilityReduceTransparency`、`accessibilityDifferentiateWithoutColor`、`colorSchemeContrast` | 首先检查框架默认结果，只在不足处补充。若图表缺失／部分语义不够，再提供 `accessibilityChartDescriptor`；不用覆盖层吞掉 mark 的可访问元素 |

**验收方法与可核对预期。** 先验证金额、数据口径和保存结果，再验证外观；截图不能证明网络保存、手势、VoiceOver 或触觉通过。以下是待实施的验收场景，当前未运行 App。
