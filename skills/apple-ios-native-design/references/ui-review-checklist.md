# UI Review Checklist 与证据协议

核验日期：2026-09-14。下列 **[S]** 条目、优先级、抽样矩阵与记录格式是本 skill 的工程验收方案；其设计依据来自文末 Apple 官方资料，不是 Apple 的认证或 App Store 审核结论。

## 1. 确定审查范围

- [ ] 写清楚当前产品任务、主要用户、入口与完成条件。
- [ ] 列出本轮变更页面、共用组件及可能受影响的邻近流程。
- [ ] 记录最低支持 OS、目标 OS build、Xcode/SDK 版本、设备/模拟器、方向、窗口可用尺寸和代码版本。
- [ ] 区分设计稿、原型、SwiftUI Preview、可运行 App；不要把某一种证据当成另一种。
- [ ] 逐项设为 `PASS / FAIL / NOT_TESTED / N/A`；未勾选默认不是通过，N/A 必须说明理由。
- [ ] 使用能体现真实长度、数量、图片比例和异常状态的测试内容；截图中的示例数字不冒充真实数据。

**[S]** 若目前只有 Windows、没有 Xcode/Apple 运行设备，完成资料与静态审查，列出待执行流程及所需环境。可以交付设计体系；不能宣称 App 已构建、交互已验证或辅助功能已通过。

## 2. 不同证据能证明什么

| 证据 | 可支持的结论 | 不能单独证明 |
|---|---|---|
| 需求/流程图/组件规格 | 设计意图、任务覆盖、导航与状态约定 | 代码实现了这些约定 |
| 源码审查 | API 使用、可用性保护、状态及辅助功能声明 | 真实布局、朗读结果、帧率和操作体验 |
| 静态截图 / 设计稿 | 当时尺寸与状态下的排版、层级、遮挡、部分对比问题 | 返回手势、键盘、焦点、运行状态、触觉 |
| SwiftUI Preview | 指定环境和数据下的布局；交互 Preview 可覆盖部分局部状态 | 全 App 导航、生命周期、真机服务、所有辅助技术 |
| Build / 单元测试 | 指定目标的编译与所断言逻辑 | 视觉正确、触摸舒适、状态流程全部合理 |
| 模拟器运行 + 操作记录 | 指定 OS/尺寸下的导航、输入、滚动和可复现状态 | 真机触觉、设备相机行为、真实 GPU/耗电 |
| Accessibility Inspector / 自动审计 | 部分缺失标签、对比、文本裁切和可访问结构问题 | VoiceOver 全流程可理解、所有自定义手势可完成 |
| 真机任务测试 | 实际手势、辅助技术、键盘、触觉及硬件相关体验 | 未测机型、OS、语言或其他用户的普遍体验 |
| Instruments / 性能记录 | 记录期间的卡顿、主线程与渲染开销 | 未记录场景或所有设备上的性能 |

Apple 将 Accessibility Inspector 定位为辅助测试信息；应从使用者角度实际操作辅助技术。[Accessibility Inspector](https://developer.apple.com/documentation/accessibility/accessibility-inspector)、[Performing accessibility testing](https://developer.apple.com/documentation/accessibility/performing-accessibility-testing-for-your-app)

## 3. 产品任务与信息层级

- [ ] 不依靠讲解即可识别页面目的和下一步；主要操作与当前任务有关。
- [ ] 顶层分区、层级详情、临时任务各有合适容器，返回、关闭和取消含义一致。
- [ ] 关键操作不只藏在长按、滑动、拖拽或无标签图标里；高级捷径有可发现的替代入口。
- [ ] 详情返回原列表后，选择与滚动位置按预期恢复；切换分区不意外丢失工作。
- [ ] 小窗口或工具栏溢出时，完成任务所需操作仍可找到；主要内容不被永久工具占满。
- [ ] 允许品牌表达，但字号、留白、内容和功能优先级不依赖装饰补救。

## 4. 页面状态与操作闭环

- [ ] 首次进入、加载、内容就绪、刷新、空内容、无搜索结果的含义可区分。
- [ ] 加载反馈与实际任务相符；长任务有必要的取消或继续处理约定。
- [ ] 离线、失败、权限拒绝和部分数据加载失败有适用的解释与恢复入口。
- [ ] 新建/编辑的保存、取消、下拉关闭、系统返回都与草稿和丢失风险约定一致。
- [ ] 快速重复点击、返回后重进、取消进行中的请求不会重复提交或显示过期成功。
- [ ] 删除或其他有后果的操作有与风险匹配的确认、撤销或恢复；不为每次普通点击弹确认。
- [ ] 错误靠近相关输入且说明修复方法；修复时保留其他有效输入。
- [ ] 搜索提交、清除、取消、加载与无结果可实际操作；结果标签与查询范围一致。
- [ ] 前后台切换、尺寸变化和必要的恢复场景不会产生无法退出的覆盖层。

## 5. 原生组件、布局与视觉

- [ ] 使用适合任务的系统组件；自定义替换能指出系统组件无法满足的具体需求。
- [ ] safe area、滚动边缘、系统栏、Home indicator 和键盘不遮挡主要内容或完成操作。
- [ ] 文字放大能换行、增高或重排；没有用统一缩字、强制单行或限制 Dynamic Type 掩盖问题。
- [ ] 文本、图标、数值和分组有清晰对齐关系；长标题、空值和极端数字无歧义。
- [ ] 图像按意图缩放/裁切，重要主体不被遮挡；不把资源图片拉伸成另一比例。
- [ ] 文字和符号使用语义层级；禁用、选中、加载和破坏性状态可分辨。
- [ ] 触控区域与相邻间距可准确使用；自定义触控目标以 Apple 的 44×44 pt 指导检查，视觉图标不必等于点击区域。
- [ ] 对特殊紧凑系统控件或专业画布，记录依据和替代操作；不把 44 pt 机械套成每种视觉元素的固定尺寸。
- [ ] SF Symbols 的名称、版本、渲染模式、字重与语义符合当前组件；装饰图标不制造重复朗读。

触控基准来源：[UI Design Dos and Don’ts](https://developer.apple.com/design/tips/)。其他条目是本 skill 对具体实现的检查，不主张存在统一卡片圆角、间距或 Tab 数量。

## 6. 材质、颜色与动态效果

- [ ] 内容与导航/控制层清楚分离；Liquid Glass 没有全面铺进列表、正文或绘图区。
- [ ] clear 只在适合背景且可读性已验证的控制使用；明亮媒体、字幕和滚动内容下也可操作。
- [ ] 系统已提供材质的组件无意外第二层玻璃；自定义效果不会遮盖系统自适应。
- [ ] 玻璃分组静止时不会错误粘连，展开/收起时身份和操作位置可追踪。
- [ ] 品牌色、警示色和数据色有明确职责；信息没有只依赖颜色或透明度。
- [ ] 浅色、深色、增强对比度与降低透明度时，文字、控件边缘和状态仍可辨认。
- [ ] 对自定义颜色用 Accessibility Inspector 或对比度工具实测：多数文本以 4.5:1、非文字控件/状态以常见的 3:1 指导为检查起点；字号/字重等条件按 Apple 当前表格判断。透明材质检查实际合成背景，不能只测资产色值。
- [ ] Reduce Motion 后仍有清楚的状态反馈；动效可打断，快速重复操作不造成跳位或卡住。
- [ ] 27 系统外观偏好改变后仍可读；未取得相关 OS 则标 NOT_TESTED。
- [ ] 触觉与结果同步且无双重触发；关闭触觉或无硬件支持时仍可完成任务。
- [ ] 使用代表性的真实内容数量连续滚动并执行主要过渡；观察到卡顿时保留轨迹再定位，不凭模拟器速度或静态截图承诺性能。

细则见 [材质与动效](materials-and-motion.md)；不要只比较一张“最漂亮”的截图。

对比度基准补充核验于 2026-09-15：[Apple Sufficient Contrast evaluation criteria](https://developer.apple.com/help/app-store-connect/manage-app-accessibility/sufficient-contrast-evaluation-criteria)。按其指导同时检查默认与相关提高对比度配置；这是一项测量方法，不代表完成本清单就获得 App Store 辅助功能声明资格。

## 7. 辅助功能、本地化与图表

- [ ] 用 VoiceOver 从入口完成一条核心任务：目的、值、操作和结果反馈可理解，焦点顺序合理。
- [ ] 图标按钮有可理解名称；Toggle、Slider、选择控件暴露真实状态，非交互装饰不过度进入焦点序列。
- [ ] 模态出现、错误出现和关闭后焦点有合理去处；动态内容不反复抢焦点或连续播报。
- [ ] 自定义手势提供可访问动作；适用时通过 Voice Control / Switch Control / Full Keyboard Access 操作。
- [ ] 至少一种长文本语言与产品所需 RTL 语言得到验证；leading/trailing、混合文字和方向性符号符合语义。
- [ ] 不机械镜像照片、品牌标记、图表轴和所有符号；先区分内容方向和界面方向。
- [ ] 日期、数字、货币、单位、复数和输入解析遵循场景及 locale；不能只翻译标签。
- [ ] 图表的单位、范围、缺失值、时间区间与刻度没有误导；图例与选中状态可区分。
- [ ] 图表信息能通过可访问描述/数据浏览或合适的等价摘要获取；若精确取值是核心任务，替代方式能获取精确值。
- [ ] 图表选择、横向拖动、缩放与页面滚动不冲突；VoiceOver 和键盘需要的操作有途径。

自定义控制检查依据：[WWDC26 Refine accessibility for custom controls](https://developer.apple.com/videos/play/wwdc2026/220/)。RTL 实现参照：[Get it right (to left)](https://developer.apple.com/videos/play/wwdc2022/10107/)。图表条目是本 skill 的数据体验验收，专项实现按本技能图表参考资料执行。

## 8. 按风险抽样的适配矩阵

**[S]** 不跑所有维度的笛卡尔积。先覆盖核心路径的基线；再覆盖每种变更的敏感边界；出现故障后增加相邻组合。记录未测组合及理由。

| 维度 | 最少选择方法 | 重点触发扩展 |
|---|---|---|
| OS / SDK | 最低支持 OS + 当前目标 OS；注明 build；分支两端各执行核心操作 | 新 API、26/27 材质差异、系统容器变化 |
| 设备 / 窗口 | 一个紧凑宽度和一个宽窗口；记录可用宽高；支持的方向 | 自适应导航、工具栏溢出、iPad 多窗口、27 iPhone 窗口调整 |
| Dynamic Type | 默认 + 最大常规字号 + 最大辅助功能字号；重点验证受影响页面的可达性与重排 | 固定高度、图表、Form、双列与长按钮文案 |
| 外观 / 材质 | 浅色 + 深色；受影响自定义材质追加降低透明度、增强对比度、可用的玻璃偏好 | clear、图片背景、自定义 tint 或资产变体 |
| 语言 / 地区 | 主语言 + 长文本样本；产品支持 RTL 时选一种实际 RTL locale | 文案/日期/数字/自定义绘制/方向性布局变化 |
| 辅助技术 | VoiceOver 核心任务；自定义手势追加替代动作与相关输入技术 | 焦点、模态、图表、复杂自定义控件 |
| 键盘 / 输入 | 软件键盘显示/隐藏、最后一个字段、提交与取消；支持时外接键盘 | Form、搜索、Sheet detents、底部操作栏 |
| 数据 / 网络 | 真实长度正常内容 + 空/失败；相应边界选长列表、极端值、离线等 | 新增异步状态、分页、保存重试、图表范围 |
| 运动 / 硬件 | Reduce Motion；触觉/相机等在相关真机验证 | 自定义转场、交互玻璃、Core Haptics、设备输入 |

可组合的高风险样本：`紧凑窗口 + 大字号 + 长标题`、`深色 + clear + 明亮图片`、`编辑 Sheet + 键盘 + 最后一个字段`。选择有共同失效原因的组合，而非任意全开。

27 的可调整尺寸背景来源：[WWDC26 What’s new in SwiftUI](https://developer.apple.com/videos/play/wwdc2026/269/)。系统辅助功能切换方法：[Testing system accessibility features](https://developer.apple.com/documentation/accessibility/testing-system-accessibility-features-in-your-app)。

## 9. 问题优先级、审查完成与验收通过

**[S] 模式边界：** Review 仅要求发现、解释和记录问题，不因发现问题而自动授权修复。下表的修复要求用于已授权的实现/修复与验收任务；只读审查将其转化为建议及复测条件。

| 级别 [S] | 判定 | 已授权实现/验收中的处理 |
|---|---|---|
| P0 阻断 | 核心任务无法完成、无法退出、错误提交/丢失输入；目标用户使用辅助技术也无法完成核心任务 | 修复并复测相关核心路径，或明确交付被阻断；不能“视觉平均分及格”抵消 |
| P1 重要 | 主要操作难发现、关键文本不可读、常用尺寸严重裁切、重要状态/恢复缺失 | 本轮修复；若受外部条件阻挡，列出具体影响和待解决事项 |
| P2 一般 | 可完成任务但造成局部误解、效率下降或明显平台不一致 | 按用户影响排序；改动后复测受影响样本 |
| P3 打磨 | 不影响理解与完成的细微对齐、节奏、装饰差异 | 结合收益与范围处理，不为微小差异重写架构 |

按受影响用户和任务后果分级；辅助功能问题不自动降为打磨。`NOT_TESTED` 是证据状态，不等同于 P0 或没有问题。

**[S] 审查完成条件：** 已覆盖约定范围，发现有依据、优先级、影响和最小修复建议；待验证疑点与已观察问题分开；清楚记录证据限制。报告可以包含未修复的 P0/P1，仍可完成本轮只读审查。

**[S] UI 验收通过条件：** 约定范围内无未解决 P0/P1；相关 P2/P3 已修复或有明确处理记录；必要场景有实际证据，剩余未测项及其影响清楚。缺少必要运行环境时只能声称“静态/方案审查完成”，不能声称“UI 验收通过”。

## 10. 证据记录格式

```text
Review ID / 日期：
范围 / 代码版本：
核心任务及完成条件：
环境：Xcode + SDK；OS build；设备/模拟器；窗口宽高；方向
设置：locale；Dynamic Type；外观；辅助功能；输入方式
测试数据 / 起始状态：
步骤：入口 → 操作 → 预期结果
实际结果：
证据：截图/视频/日志/测试结果路径；必要时帧或时间点
条目状态：PASS / FAIL / NOT_TESTED / N/A（附原因）
问题：优先级；影响；可复现步骤；建议最小修复
复测：相同触发组合结果；必要的相邻回归
未验证：具体场景；缺失环境/数据；下一步
```

**[S]** 汇报使用“在 X 环境完成 Y 流程，观察到 Z”，不要用“完全原生”“100% HIG 合规”“所有机型通过”。记录的是可核验的体验，不是主观审美分数。
