# Skill 行为评估与维护

仅在创建、修改或评估本 skill 时读取，不在普通 UI 任务中默认加载。本文件的方法与标准均为 **Skill**；它验证 agent 的可观察决策与交付，不把文字格式相似当成设计质量。

## 评估方式

1. 选取受修改影响的真实任务，让独立执行者只看到任务、skill 和最少原始资料；不给预期答案或已知缺陷。
2. 让执行者按正常触发与路由使用 skill。单独保存输出，避免写入被评估的项目或生产环境。
3. 依据下表比较实际行为：是否满足用户任务、选择合理、守住数据/版本/状态契约、有证据且不过度扩大范围。
4. 只针对观察到的失败改规则；不要为一个特殊案例积累无条件禁令。
5. 文档/模拟场景评估不能证明 SwiftUI 编译、运行交互或视觉质量。需要这些结论时，用相同具体项目、数据、SDK/OS 做实测。

## 场景池

评估者可用以下情境设计新问题；不要将“观察重点”交给独立执行者作为答案提示。

| 情境 | 观察重点 |
|---|---|
| iOS 17+ 记账 App，新建账目与月度分析，希望采用 iOS 27 设计语言 | 最低 OS 不被提高；信息结构、草稿、保存失败、键盘、图表口径明确；玻璃有条件采用 |
| UIKit 内容 App，只要求调整详情页操作层级 | 沿现有 UIKit，局部修改；不强制迁移 SwiftUI或安装依赖 |
| 图片丰富的播放页，想把全部按钮、字幕和列表做 clear 玻璃 | 能指出内容/控制职责与对比问题，提出保留品牌表达的方案；不虚构 HIG 禁止所有定制 |
| 只给一张设置页截图要求 UI Review | 能说明观察依据与影响；不声称键盘、VoiceOver、点击和保存已经通过；不自动改代码 |
| 30天数据中有缺失、退款负数和不完整日，要求比例及趋势 | 核对分母/时间粒度；不把缺失归零、不用带负值数据强画饼图；给可访问明细 |
| 三列内容库需要适配窄窗口、大字和 RTL | 按实际空间折叠，保留选择/导航状态；不按设备名或固定横屏判断全部行为 |
| 用户要求某个新 SF Symbol 用于 iOS 16 | 查具体符号版本与回退，不能通过字符串猜测可用性 |
| 页面设计要求自定义品牌字体、插画和密集专业信息 | 允许有理由的定制；确保文字缩放、任务效率和系统交互，不套统一卡片风格 |
| 用户只要修复 Swift 服务层 JSON 解析错误 | 不因 iOS/Swift 关键词扩展为 UI 设计，不加载图表/材质大全 |
| 用户明确只要设计方案，没有实现请求 | 交付可审阅的方案和验收条件，不擅自创建/安装/部署 App |

## 判定维度

- **触发与范围**：正确选择 Design / Implement / Refine / Review；无无关工作或虚构授权。
- **设计质量**：选择与用户任务、内容结构和平台习惯相关；重大例外有理由，不追求表面装饰一致。
- **行为完整性**：相关入口、返回/取消、保存、异常与恢复能对应实际数据模型。
- **技术真实性**：API、重载、图标和 SDK/OS 基线准确；不将模板版本等同于实现支持。
- **包容性**：文字、输入、辅助技术、语言和可用空间作为实际设计条件。
- **数据真实性**：指标、口径、缺失、基线、范围和交互选择不误导。
- **证据与诚实**：区分设计推断、静态观察和实际测试；不以格式校验代替行为验证。
- **上下文效率**：只读相关参考，输出与任务规模相称；不会为小改动展开完整审计。

使用 `满足 / 部分满足 / 不满足 / 未测试` 并附具体证据。不能用平均审美分数抵消虚构 API、数据误导、输入丢失或不可达的核心流程。

```text
实际行为与关键证据：
各维度结果：
发现的问题 / 修改 / 定向复测：
未验证能力：
```

初版仅有场景检查时应这样表述。若要证明“使用 skill 后比不使用更好”，需要固定模型/环境/任务，进行有无 skill 的多场景对照并由独立评审比较；不能从一次通过推断稳定提升幅度。
