# 页面模式与交互契约

这些是基于 HIG 与原生组件组合的 **[Skill] 工程模式**，不是 Apple 发布的固定页面模板。只加载本次任务需要的模式；不可为了“完整”给产品添加不需要的页面或功能。组件选择详见 [component-decisions.md](component-decisions.md)，数据可视化详见 [charts.md](charts.md)。

**标记：** [HIG] 为 Apple 建议；[API] 为官方组件语义；[Skill] 为本体系制定的交互与验证要求。未单独标记的场景规则均为 [Skill]。系统能力和版本按项目核验，不将 iOS 27 资源中的某个静态布局当作所有设备的固定尺寸。

## 通用状态契约

设计每条关键路径时，按实际会出现的状态填写以下项目；不适用写明原因，不必为静态本地页面编造网络状态。

| 状态 | 用户应理解的内容 | 行为契约 |
|---|---|---|
| 首次进入/加载中 | 正在准备什么，当前是否可操作 | 只阻塞依赖未就绪数据的区域；进度不可伪造 |
| 有内容 | 当前范围、主要内容、下一步 | 当前选中项与导航标题一致 |
| 真正空内容 | 尚无项目的原因 | 相关时提供新建/导入或了解功能入口 |
| 搜索/筛选后为空 | 当前条件没有结果 | 可清除或修改条件；与首次空状态区分 |
| 局部失败/旧数据 | 哪块不可用、旧内容是否仍有参考价值 | 保留有用内容并提供对应重试，避免全屏闪退回加载 |
| 完全失败 | 什么无法完成、如何恢复 | 可重试、退出或使用可用替代路径 |
| 编辑/提交中 | 当前变更是否已保存 | 防止重复提交；取消与离开遵循保存策略 |
| 成功/被中断 | 已发生什么、接下来去哪 | 恢复目标上下文，保留需要继续的工作 |

先选用户能理解的状态文案，再选图标和动画；不得用一个旋转图标无限代替所有失败情况。长任务在有准确数据时使用确定进度，在适宜时提供取消。[HIG，P1]

## 1. 列表—详情 / 内容库

**适用：** 用户需要扫描集合、选择对象并查看或操作详情。示例：账目、笔记、任务、联系人、文档。

- 文字为主选 `List`；对象依赖封面或图片识别时评估网格。宽窗口需要并排关系时使用 `NavigationSplitView`，窄窗口折叠后仍维持同一信息层级。[HIG/API，P2–P4]
- 定义每行的主标题、必要次要信息、状态和动作范围；被点击的区域应对应清晰结果。不要同时让全行进入详情、嵌套按钮又被全行点击吞掉。
- 详情页先明确对象身份，再组织内容和与对象有关的动作。列表中的关键状态与详情保持一致，不能把筛选前对象名称留在标题里。
- 保留用户返回集合时有价值的位置与条件；对象被删除、共享权限失效或深链对象不存在时给出说明与返回集合入口。
- 用原生 swipe actions / context menu 提供加速路径，同时给关键操作可发现的入口；多选、批处理和重排只在确有任务需要时提供。

**状态：** 首次空、刷新保留旧内容、分页末尾、分页失败、删除最后一项、无选中详情、选中对象失效。是否分页/同步取决于实际数据源。

**验证：** 从列表打开详情并返回；带筛选进入再返回；删除当前对象；宽窄转换与大字号下选中关系不丢失。仅增加新容器不构成信息架构改进。

## 2. 设置 / 偏好 / 表单

**适用：** 调整应用行为、账号资料或输入结构化数据；当前任务专属的选项优先放回该任务附近。[HIG，P5]

- 默认评估 `Form` + `Section`，通过分组说明语义联系。`Form` 的子控件样式随平台变化，不从 macOS 截图照抄 iOS 交互。[API，P6]
- 开关表达状态，选择器表达值，按钮表达动作，导航行表达更深层配置。重置、清空等动作不得伪装为开关。
- 提供合理默认值并减少无必要设置；按任务和语言组织分组，不把实现层、数据库或 SDK 术语暴露给用户。[HIG/Skill，P5]
- 简单偏好可立即生效；涉及多个字段一致性的更新可使用草稿提交。选择其中一种并让离开行为、文案和错误恢复一致，不机械给所有设置加 Save。
- 依赖权限/联网的控件显示真实状态：请求中、受限制、失败回滚或待重试。用户关闭通知偏好与操作系统撤销通知权限应可区分。

**状态：** 已保存默认、已修改草稿、字段无效、权限限制、保存中、保存失败、账号会话失效。只使用与此表单有关的状态。

**验证：** 修改后离开/再进入、重启后值一致；键盘不遮挡当前字段和错误；长标签及辅助功能字号保持可读；重置动作说明影响范围。

## 3. 搜索 / 筛选 / 排序

**适用：** 用户已有查找目标，或内容规模使浏览成本增加。搜索位置依重要性与范围决定，不默认每个页面都加搜索框。

- App 范围的搜索可成为主要目的地；局部搜索应明确局部范围。当前 HIG 允许两者并存，但不能让用户猜同一查询究竟覆盖什么。[HIG，P7]
- 优先 `.searchable`，按需使用 suggestions/scopes/tokens；搜索框绑定查询状态不意味着数据已经完成搜索，结果逻辑由应用负责。[API，P8]
- 把清除文字、退出搜索、清除筛选和改变排序作为不同操作定义。筛选生效后持续显示可理解的线索，必要时显示结果数量。
- 实时结果应避免旧请求覆盖新查询；慢请求与零结果区分。进入详情再返回保留查询及有用位置，键盘焦点是否恢复按任务决定。
- 近期搜索和建议仅在有价值时呈现；涉及隐私内容时谨慎展示历史，提供清除方式。[HIG，P7]
- 多条件筛选可短流程 sheet 或宽窗口 popover；立即应用与“应用”按钮模式二选一并保持一致，取消不能意外提交草稿条件。

**状态：** 未激活、已聚焦未输入、输入/查询中、有结果、零结果、失败、已有条件、条件草稿。不要用假近期记录补视觉空白。

**验证：** 快速连续查询、清空、取消、切范围、修改筛选、详情返回；长标签、大字号和本地化不让条件消失。WWDC26 的搜索展示因 iOS、iPad 与 Mac 容器而异，照抄其中一种截图前核对平台。[P9]

## 4. 新建 / 编辑 / 多步任务

**适用：** 用户改变数据并需要知道何时生效、如何撤回。短且依赖当前上下文的任务可用 sheet；持续或复杂编辑评估专用页面/全屏工作区。[HIG，P10]

- 先填写 `数据归属 → 草稿/立即保存 → 校验 → 提交 → 失败恢复 → 关闭/取消`，再设计页面。
- 输入控件按值域选择；预填合理值并避免重复输入。必要权限或系统选择器可以减少输入，但不能以方便为由过度请求数据。[HIG，P11]
- 默认焦点需真的有助于开始任务；不要让键盘无故遮住用户先要阅读的说明。金额、日期、长文本等输入分别处理格式、范围和辅助功能。
- Save/Create/Send 表达实际结果；Done 不自动等于“网络已保存”。提交失败留住草稿，重复点击不重复创建；成功后返回有意义的上下文并展示新对象或改变后的状态。
- 未保存关闭需要有明确政策：保留草稿、明确放弃，或提示选择。Back 返回上一步；取消整个流程的入口和后果不同。没有变更时避免无意义的丢弃确认。
- 多步任务保留前面输入，步骤描述按实际工作组织；进度与未完成要求清楚，不为视觉效果拆成多屏。系统非模态 sheet 可用于与父内容协作的选择任务。[HIG/Skill，P10]

**状态：** 新草稿、编辑现有对象、无修改、有修改、无效、提交、成功、失败、对象并发变化、中断恢复。并发冲突只在产品存在相应数据模型时设计。

**验证：** 下拉关闭、Cancel、Back、完成动作、键盘提交、切后台再回来；每条退出路径符合数据政策。对重要失败做真实流程验证，不能以按钮动画代替保存结果。

## 5. 内容 / 媒体 / 阅读

**适用：** 用户以内容消费、浏览或播放为主。先保证文字、图像、音视频的阅读体验，再放置控制层。

- 文章用可读宽度和自然滚动组织；图像集合使用稳定可理解的网格。不要在用户观看时无原因重排对象。[HIG，P2]
- 工具栏、底部附件或播放控制服务当前内容；定制插画、封面和排版可表达品牌，仍保留熟悉的返回、分享、选择、缩放等交互。
- 媒体或背景可延伸至窗口边缘，关键控件遵守安全区域；宽窗口避免把正文无限拉宽。状态栏/控制层隐藏需给内容带来实际价值，并提供可发现的恢复方式。[HIG，P12]
- 若使用全屏或自定义手势，明确入口、退出及辅助输入；关键功能不能只依靠隐蔽手势。专业绘图、相机、游戏等需要专项设计，不能强套普通表单。[HIG/Skill，P13]
- 播放、缓冲、暂停和失败保持可区别；是否自动播放、背景播放和音频策略必须来自产品需求和系统能力，不由“Apple 风格”替用户决定。

**状态：** 媒体占位、可播放、缓冲、暂停、失败、下载中/离线不可用（若支持）、权限限制。辅助说明不伪造实际播放状态。

**验证：** 控制层显示/隐藏、横竖屏和窗口变化、缩放后退出、系统中断；如存在音视频内容，同时核对字幕、替代信息和系统播放控制的使用。

## 6. 首页摘要 / 仪表板

**适用：** 用户回来时需要快速理解当前情况并继续任务。不是所有应用都需要独立“首页”；若它只复制列表或 Tab 链接，可直接以核心内容为入口。

- 先写出首页要回答的问题，例如“今天要处理什么”或“最近变化是什么”；按答案组织信息层级，而不是先画同尺寸指标卡。
- 摘要显示关键数值时带单位、时间范围和必要的数据时效；空白、零值、未采集和加载失败不同，不填演示数值冒充数据。
- 行、分组、图文区和卡片按语义选择；可点击摘要需有清楚目的地，进入详情后保留相同时间和筛选上下文。
- 图表必须支持真实阅读任务；选择、轴、图例、可访问描述、比较公平性与下钻遵循 [charts.md](charts.md)，不因为“高级感”加入无解释曲线。
- 使用一条清晰的主要工作路径和可理解的次要入口；需要多项同等紧急工作时可以并列，但视觉权重应反映真实优先级。

**状态：** 首次无数据、部分数据就绪、时间范围改变、旧数据、局部失败、有紧急事项、所有任务已完成。

**验证：** 用真实极值、长名称和局部缺失审查页面；窄/宽窗口阅读顺序一致，大字号时重排；每个摘要可追溯数据范围和对应详情。

## 7. Onboarding / 上下文帮助 / 权限

**适用：** 核心操作不能通过界面自然理解，或任务开始前确有必要信息。一般优先让人尽早体验价值，必要引导简短、可跳过、尽可能通过实际操作学习。[HIG，P14]

- 区分启动画面、介绍、必要账户设置、教程和系统权限，它们解决不同问题；不把所有步骤串成首次启动的强制门槛。
- 按上下文提供帮助；可评估 TipKit，但不能用提示弥补无法理解的按钮。已完成或主动关闭的提示不要持续遮挡操作。[HIG/Skill，P15]
- 权限在相关功能需要时请求，说明具体用途；被拒绝后保留仍可用的功能并给出相关恢复路径。不能伪造系统权限弹窗或把同意预先选中。[HIG/Skill，P16]
- 如果确需紧接系统授权弹窗的解释页，当前 HIG 建议只提供一个明确进入系统弹窗的 Continue/Next，不在该解释页增加 Cancel/Close；选择由随后的系统弹窗承接。这与可跳过的一般 onboarding 不同。中性说明用途，不用“允许”假装已授权、不以操纵性画面诱导。[HIG，P16]
- 与照片、文件等有限选取任务相关时，先评估系统 picker 是否足够，避免把用户选一项内容升级为整个资料库权限需求；具体授权方式查相关框架文档。

**状态：** 首次/回访、已完成/跳过引导、权限未决定/授权/拒绝/受限制、只授予有限范围、从系统设置返回。不是所有权限 API 都具备相同状态集合。

**验证：** 全新安装、跳过教程、拒绝权限、只授权有限范围、之后更改授权；核心可用部分仍可进入，不无限重复弹出请求。
