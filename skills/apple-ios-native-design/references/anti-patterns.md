# Anti-patterns：识别原因，再做最小修复

用于 Refine / Review 或实现后自查。本表是 **Skill 的综合诊断规则**；它列出常见失败的条件和修复方向，不把某种组件、风格或布局绝对禁用。具体官方依据、API 版本和例外由链接的专题说明。

先确定用户任务与可观察影响，再报告问题。代码中出现某个 modifier 只是检查线索，不能自动判错；不把主观“看着不像 Apple”当成问题证据。

## 信息结构与交互

| 反模式与触发条件 | 用户代价 | 修复方向 / 合理例外 |
|---|---|---|
| 新增、保存被放进一个没有内容的 Tab | 目的地与动作含义混淆，返回状态难理解 | 改成语义按钮/工具栏；真正的创作工作区可以是目的地 |
| 所有详情都弹 Sheet | 浏览层级与退出关系不清楚 | 层级详情用栈；与当前上下文有关的短任务仍可用 Sheet |
| 为了统一外观把 Back、Cancel、Save 都写成 Done | 用户无法预测数据何时生效、如何放弃 | 先定义保存策略，再给动作命名 |
| 叠很多 Sheet 或自绘抽屉，缺少清楚退路 | 焦点、键盘和返回行为混乱 | 评估单一呈现内部步骤；确需多层时逐条验证退出与焦点 |
| 禁止下拉关闭且不给其他退出方式 | 用户被困，可能丢失工作 | 防止丢数据的同时提供明确完成/取消/保留草稿路径 |
| 关键动作只有长按、滑动或拖动入口 | 新用户和辅助技术使用者无法发现 | 保留捷径，补可见或可访问的等价入口 |
| 每次成功、删除或轻微输入错误都弹 Alert | 普通任务反复中断，确认失去意义 | 按后果使用就地反馈、撤销、确认；不可恢复行为仍需要匹配的保护 |
| 取消、关闭和失败都清空有效输入 | 人需要重新工作，失去信任 | 明确草稿归属与保留范围，只有明确放弃才丢弃 |
| 只有理想成功状态 | 等待、失败或拒绝后出现死路 | 按真实数据和服务契约补状态，不虚构不存在的离线/恢复功能 |
| 用假进度或提前显示成功掩盖延迟 | 状态不可信，可能重复操作 | 进度未知时如实展示等待；反馈与真实业务结果同步 |
| 任意数量或空白 Tab 只为对称 | 导航成本增加，信息架构失真 | 用真实主要目的地组织；按窗口与定制情境处理数量 |

依据与细则：[组件决策](component-decisions.md)、[页面模式](screen-patterns.md)。

## 视觉、布局与材质

| 反模式与触发条件 | 用户代价 | 修复方向 / 合理例外 |
|---|---|---|
| 给每块信息加相同卡片、阴影和强调色 | 所有内容同等突出，难找重点 | 按任务建立层级；独立对象和真实分组仍可以用卡片 |
| 自绘导航栏仅为模仿某张系统截图 | 系统返回、适配、滚动与辅助功能可能丢失 | 先用原生栏和受支持定制；专门工作区另论并落实行为契约 |
| 固定 screen 宽高、刘海高度、底部安全距离 | 窗口、键盘和设备变化时遮挡或空白 | 使用实际可用空间、安全区与系统容器 |
| 用“设备是 iPad / 方向是横屏”作为唯一布局判断 | iOS 27 可调整窗口等场景下布局错误 | 按容器空间、size class 与内容重排；设备能力判断与布局判断分开 |
| 全局固定字体高度、单行、缩小文字或限大字 | 关键内容不可读，动态字体名存实亡 | 换行、增高、减少列数；摘要截断需保留完整内容入口 |
| 把截图 RGB、圆角和间距命名为全局 Apple 常量 | 不同组件/版本表现失真 | 区分系统语义、已查模板实例与产品自定义 token |
| 固定白底、黑字或极低透明度辅助文字 | 深色或提高对比度时不可读 | 采用语义样式；品牌色提供环境变体并验证 |
| Liquid Glass 铺满列表、表单、图表内容 | 导航与内容争夺注意，可读性不稳定 | 玻璃匹配控制职能；内容用合适标准材料或背景 |
| 系统已有玻璃背景，又外包一层玻璃 | 材质叠加，层级和边缘混乱 | 先移除重复包装，检查系统容器提供的效果 |
| 用 blur/opacity 冒充完整 Liquid Glass | 缺少系统的交互、光学及可访问性行为 | 用原生材质 API；低版本替代明确属于回退 |
| clear 用在浅色复杂背景，未经运行验证 | 标签和边界消失 | 先用更稳健的 regular；clear 必须有合适背景条件及证据 |
| 全部按钮同样高饱和 tint | 重点丢失，状态与品牌竞争 | 分配强调层级；不能机械要求品牌色只出现一次 |
| 为“灵动”不断弹跳、旋转、闪烁 | 阅读被打断，运动敏感用户受影响 | 动画对应真实状态/反馈，减少动态时保留语义 |

依据与细则：[视觉基础](visual-foundations.md)、[资源与图标](resources-and-symbols.md)、[材质与动效](materials-and-motion.md)。

## 符号、数据与可访问性

| 反模式与触发条件 | 用户代价 | 修复方向 / 合理例外 |
|---|---|---|
| 按图形相似选 SF Symbol，名称与实际动作不符 | 人预测错误操作 | 先确定对象/动作语义，不确定时用文字 |
| 符号名称或效果在低版本不可用 | 图标缺失，关键入口失去含义 | 检查具体 symbol/特性可用性，使用已核验回退 |
| 把所有符号强制 fill、多色或同一种动画 | 系统容器语义被覆盖，视觉噪声增多 | 优先保留组件变体规则，按真实状态定制 |
| 只有图标且没有可理解标签/值 | VoiceOver 无法理解动作与当前状态 | 原生 Button/Label 与必要 accessibility label/value/traits |
| 仅靠红绿或色深表达成功、系列、预测 | 信息对部分用户不可达 | 文字、线型、形状或符号共同表达 |
| 图表没有问题、单位、时间范围与口径 | 看起来完整却不能支持判断 | 先写数据契约；单值/精确查找可用文字或列表 |
| 缺失填零、截断总量柱轴、平滑伪造峰值 | 数据结论被改变 | 保留缺失语义和正确编码，解释必要的统计处理 |
| 各期相同图高使用不同量纲且不提示 | 比较产生误导 | 统一口径与可解释的域，标注不完整周期 |
| 用所有点生成复杂饼图或装饰性 3D | 比较困难，透视或遮挡扭曲感知 | 优先适合任务的二维编码；真正三维数据按需评估 |
| tooltip/拖拽是唯一精确值入口 | 键盘、辅助技术或手势冲突时无法取值 | 提供摘要、明细与可发现的替代操作 |
| 认为系统提供 Audio Graph 就已完成数据无障碍 | 摘要、缺失、单位和精确值需求可能未覆盖 | 先测试默认语义，只在不足时补充或定制 |

依据与细则：[资源与图标](resources-and-symbols.md)、[Swift Charts](charts.md)、[UI Review](ui-review-checklist.md)。

## 实现与证据

| 反模式与触发条件 | 风险 | 修复方向 |
|---|---|---|
| 有 `if #available` 就认为旧编译 SDK 能识别新类型 | 编译仍失败 | 区分 SDK 符号存在与运行系统分支 |
| TabView 的版本被套给新 Tab 语法，或把 Chart3D 写成 iOS 27 新增 | 部署目标不兼容 | 查具体类型/重载，见映射表的已核验基线 |
| 将模板版本直接改成最低部署版本 | 无授权缩小用户覆盖 | 将设计基准、SDK、最低 OS 与目标运行 OS 分开 |
| 一张截图就报告手势、焦点、VoiceOver、触觉和流畅度通过 | 验收没有证据 | 按证据能力分层，不能测试的项目标 NOT_TESTED |
| 用审美总分抵消不能完成任务或错误数据 | 严重问题被忽略 | 按实际用户后果分级，先处理阻断和重要问题 |
| 使用 skill 就安装框架或重写项目 | 超出用户范围，增加维护成本 | 沿现有架构，只有必要且已授权时增加依赖或改架构 |

## 报告与修复方法

每个发现使用：`触发条件 → 可观察结果 → 用户影响 → 最小修复 → 复测场景`。有证据再定级；未知运行结果写为待验证疑点。一次检查无需覆盖整张表，优先受改动影响的部分。完整证据协议见 [UI Review Checklist](ui-review-checklist.md)。

本表综合参考文件中已核验的 Apple 来源，研究日期为 2026-09-14；整理日期为 2026-09-15。表格本身属于 Skill 方法，不是 Apple 发布的反模式清单。
